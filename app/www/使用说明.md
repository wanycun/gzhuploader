# 公众号助手 · 使用说明

把 Markdown 文章从 NAS 本地推入微信公众号草稿箱：编辑、排版、上传、草稿管理一站完成，密钥只保存在自己 NAS 上。

## 安装

在飞牛 fnOS 应用中心手动安装与你机器架构相同的包：

- x86_64 机器用 gzhuploader-x86_*.fpk
- ARM 机器用 gzhuploader-arm_*.fpk

两个包内容完全相同，只是架构标记不同；装错架构装不上，换另一个即可。

## 第一次使用（设置页）

1. **公众号 AppID / AppSecret**：公众号后台「设置与开发 → 基本配置」里查看。
2. **IP 白名单（重要）**：在公众号后台把你家宽带的出口 IP 加入 IP 白名单，否则上传会失败。在应用「仪表盘」能看到当前出口 IP；家庭宽带 IP 变化后要重新加。报错信息里也会带上当时的出口 IP。
3. **AI 配置（可选）**：在设置页选服务商（DeepSeek / OpenAI / 通义千问 / Kimi / 智谱 / 硅基流动 / 本地 Ollama / 自定义 OpenAI 兼容接口），填密钥与模型名后，「文案生成」可用；再填一个「绘图模型」，默认封面与文案生成的正文配图会先由 AI 出图，失败自动回退程序绘制的电蓝图图。
4. **账号口径（可选）**：账号名、作者名、作者简介，用于文案生成与排版署名。

## 日常流程

仪表盘看状态 → 在「文章包」里选一篇 → 编辑改文案 → 排版页调样式后点「保存排版」→ 回文章包点「上传」进草稿箱 → 发布去公众号后台操作（本应用只到草稿为止）。

## 文章包格式（给其他 AI / 脚本投递用）

文章包就是数据目录 jobs/ 下的一个文件夹（应用内「运行日志」页可看到运行记录；数据目录为应用私有目录下的 gzh-data/jobs）：

```
jobs/<包名>/
  article.md    必需，文件头 front matter 带 title / author / digest / cover
  cover.png     封面图（文件名与 front matter 的 cover 一致）
  配图.png      正文图片，article.md 里以相对文件名引用
  spec.json     可选，排版规格（见下）
  content.html  可选，排版成品；有它时上传以它为准
```

article.md 示例：

```
---
title: 文章标题
author: 作者名
digest: 一句话摘要
cover: cover.png
---

正文 Markdown……
```

spec.json 是排版工坊的规格文件（theme / label / title / summary / sections / author / intro），有它时排版页按规格渲染；没有时排版页会按 Markdown 的 ## 小标题自动分节。

## 常见问题

- **上传报 IP 不在白名单（40164）**：把报错里的出口 IP 加到公众号后台白名单。
- **标题超限（45003）**：标题太长，缩短后再传。
- **草稿箱读不到**：多为网络或白名单问题，错误会原文显示在草稿箱页面。


## AI 接入（API)

应用内置带令牌的 API，供其他 AI / 脚本调用：建包、传图、排版、上传草稿都可远程完成。

- 在应用「设置」页点「生成 / 更换令牌」，令牌只显示一次，请当场保存。
- 接口地址：http://<NAS 局域网 IP>:10039/api/v1（或经飞牛网关 /app/gzhuploader/api/v1）。
- 每个请求带请求头 Authorization: Bearer <令牌>。
- 完整端点、示例与一段可直接复制给 AI 的 Skill 描述，见应用内「设置 → 接入说明」，或随包的《公众号助手-AI接入说明.md》。
